# omf5_data
Data related to computing quinary orthogonal modular forms

This data was generated by the code in the repositories https://github.com/assaferan/omf5 and https://gitlab.fing.edu.uy/grama/quinary.

- [Structure](#structure)
- [Additional Files](#additional_files)

## Structure

The data consists of the following
* Single rows of Hecke matrices
* Hecke matrices
* Hecke eigensystems

### Single rows of Hecke matrices
In folder **hecke_rows**, there are files named *hecke_row_{N}_{p}.dat*, for N < 1000 and p < 100 a prime not dividing N.

Each file contains a dictionary, whose keys are the possible conductors *d* for the spinor norm twist, corresponding to the different Atkin-Lehner spaces.

The value at *d* is the first row of the matrix representing the Hecke Operator *T(p,1)* on the space of paramodular forms of weight (3,0), level N and coresponding Atkin-Lehner signs.

### Hecke matrices
In folder **hecke_mats**, there are files named *hecke_mat_{N}_{p}.dat*, for N < 1000 and p < 10 a prime not dividing N.

Each file contains a dictionary, whose keys are the possible conductors *d* for the spinor norm twist, corresponding to the different Atkin-Lehner spaces.

The value at *d* is the matrix representing the Hecke Operator *T(p,1)* on the space of paramodular forms of weight (3,0), level N and coresponding Atkin-Lehner signs.

### Hecke eigenvalues beyond p < 100
Folder **hecke_evs_ext** holds raw omf5 output for T(p) at larger primes and T(p,2) at p > 7, for the spaces whose L-functions were computed. See its README.

### Hecke eigensystems of weights (4,0) and (3,2)
Folders **hecke_evs_4_0** and **hecke_evs_3_2** hold the paramodular forms of weights (4,0) and (3,2) of the levels N <= 150: 146 and 143 levels, those whose omf5 run had finished. Each **data/hecke_ev_K_J_N.dat** is in the format of **hecke_evs_3_0/data**, with T(p,2) for p <= 13 instead of p <= 7. The script *convert_weight_runs.py* wrote them from runs of omf5 at commit 855b651 with the weight and precision 200:

    omf5 -genus=GENUS -disc=N -weight=1 -prec=200      (4,0)
    omf5 -genus=GENUS -disc=N -weight=1,1 -prec=200    (3,2)

GENUS is a file in the format of *qf5.db*, with other representatives at some levels. omf5 cannot use *qf5db.sage* with a weight, because its isometries (-isom) are not supported there. The Atkin-Lehner rule below gives the same signs as **hecke_evs_3_0** for all 691 forms of the weight-0 runs with GENUS (N <= 150).

omf5's weight (a, b) is the paramodular weight (a - b + 3, 2b). omf5 divides T(p) and T(p,2) by p^a and p^(2a), so the eigenvalues are algebraic integers. The spinor Euler factor at a good prime is then 1 - T x + p (T2 + p^(2a) (p^2 + 1)) x^2 - p^(2a+3) T x^3 + p^(4a+6) x^4.

- 'aut_rep_type' is the type omf5 gives, except that a form of type G is marked old ('O') when its eigenvalues at the primes not dividing N are those of a form of type G at a level M < N dividing N. The eigenvalues are compared through their characteristic polynomials, since the field_poly depends on the level. So the forms of type G are the new non-lifts. There is no lattice of discriminant 1, so an old form from level 1 would not be found. There are none: the cusp spaces of level 1 of both weights are 0.
- The Atkin-Lehner signs follow the rule for weight 0 (see below). The sign at p is e_p, negated if p divides the conductor of the spinor character. The script reads the Eichler invariant e_p off the sign of the constant form in **hecke_evs_3_0/data**.
- The new forms of type G of degree at most 20 have a Hecke ring and eigenvalue coordinates, computed as in *add_coordinates_14_20.py*. Their field records are in **fields.json**, in the format of **hecke_evs_3_0/fields.json**. The other forms have traces only. That covers all but 1 G orbit of weight (4,0) and 12 of weight (3,2), whose degrees go up to 25 and 40. These G orbits also have 'trace_lambda_p_squared', the traces of T(p)^2 at the primes of 'trace_lambda_p_square', which the traces of T(p^2) need.
- **summary_K_J.json** gives, for each level, the dimension of the new forms of type G for each Atkin-Lehner string, and the number of forms of each type.

At every level N <= 150 where the LMFDB has the space (the squarefree levels), the dimension of the new forms of type G equals its new_cusp_G_dim: 90 levels of weight (4,0) and 88 of weight (3,2). Over all the levels there are 290 and 468 new G orbits, of total dimension 890 and 1947. The forms 2.K.31.4.0.a.a and 2.K.19.3.2.a.a have the eigenvalues and Atkin-Lehner signs stored in the LMFDB.

### Hecke eigensystems
Folder **hecke_evs_3_0** contains three subfolders - **data**, **data_nl_200** and **logs**.
The subfolder **data** contains files named *hecke_ev_3_0_{N}.dat*. Each file contains an array of dictionaries, each dictionary corresponds to a modular form in the space of 
orthogonal modular forms of trivial weight and level N, corresponding to Siegel modular forms.
The fields for each modular form are as follows.

* 'aut_rep_type' : 'F', 'P', 'Y', 'G' or 'O', the automorphic type of the associated automorphic representation (F/P/Y/G) or 'O' if this is an oldform. (appears at lower level) A Saito-Kurokawa lift is of type 'P' only at the level of the classical form it lifts, and 'O' at every higher level. (Until 2026-11, 1825 lifts of forms of lower level were typed 'P', for example the lift of 16.4.a.a at level 976 and the lifts of the level-256 forms at level 768; *fix_old_lifts.py* retyped them 'O', in **data** and in **data_nl_200**.)
* 'field_poly' : The coefficients of the defining polynomial of the Hecke field (the field over which the Hecke eigenvalues are defined), given as [a_0,...,a_n] where f(x) = a_0 + ... + a_n x^n.
* 'hecke_ring_power_basis' : True if the eigenvalues are represented by the coordinates in the power basis [1, a, a^2, ..., a^{n-1}] where a is a root of the field polynomial f(x).
* 'hecke_ring_numerators' : If hecke_ring_power_basis if False, an array of arrays, each representing an element in the field in the above power basis, corresponding to numerators of generators for the Hecke ring.
* 'hecke_ring_denominators': If hecke_ring_power_basis if False, an array representing an element in the field in the above power basis, corresponding to a denominator of generators for the Hecke ring. That is, if a_1,...,a_n are the numerators and b is the denominator, then a_1/b,...,a_n/b are generators for the Hecke ring.
* 'hecke_ring_inverse_numerators': Same as above, but for the inverse generators (writing the power basis as a linear combination of the generators).
* 'hecke_ring_inverse_denominators': Same as above, but for the inverse generators (writing the power basis as a linear combination of the generators).
* 'lambda_p' : an array of arrays, representing the eigenvalues of the form with respect to the Hecke operator *T(p,1)* in the supplied basis of the Hecke ring for prime p < 100 not dividing N.
* 'lambda_p_square' : an array of arrays, representing the eigenvalues of the form with respect to the Hecke operator *T(p,2)* in the supplied basis of the Hecke ring for prime p < 100 not dividing N.
* 'trace_lambda_p' : an array of the traces of the elements of 'lambda_p'.
* 'trace_lambda_p_square' : an array of the traces of the elements of 'lambda_p_square'.
* 'atkin_lehner_eigenvals' : an array of pairs [p, e], one for each prime p dividing N in ascending order, where e = 1 or -1 is the eigenvalue of the paramodular form under the Atkin-Lehner operator at p.
* 'atkin_lehner_string' : a string of '+' or '-', corresponding to the Atkin-Lehner eigenvalues at the different primes in ascending order.
* 'hecke_ring_index' : The index of the Hecke ring inside the ring of integers of the number field.
* 'hecke_ring_generator_nbound' : The smallest n such that the eigenvalues lambda_j with j <= n generate the Hecke ring, where lambda_j is the eigenvalue of *T(p,1)* for j = p and of *T(p,2)* for j = p^2 (primes dividing N are skipped). It is 1 when the Hecke ring is Z (lambda_1 = 1). Reproducing the Hecke ring needs the eigenvalues of *T(p,2)* only for p <= sqrt(n).

The Hecke ring is the order generated by all the eigenvalues in 'lambda_p' and 'lambda_p_square'. The basis given by 'hecke_ring_numerators' and 'hecke_ring_denominators' is a Z-basis of it, starting with 1 as the pages and the classical modular forms expect (1, beta_1, ..., beta_{d-1}): the other elements are LLL-reduced against the coordinates of the lambda_p, so that these are small, as in the LMFDB's classical modular forms. The eigenvalues are given by their coordinates in it. (Until 2026-11 it was Sage's basis of the order, which need not start with 1; *rebasis_hecke_rings.py* changed it.) Eigenvalue coordinates are given for the orbits of types G, P and Y of degree at most 20, and of type O of degree at most 13 (and 71 records of type O of degree 14 to 20, which were typed 'P' until *fix_old_lifts.py*); for the other orbits 'lambda_p' and 'lambda_p_square' are empty and only the traces are given.

(Before the Hecke rings were recomputed, the stored "Hecke ring" was the ring of integers, with 'hecke_ring_index' 1 and 'hecke_ring_generator_nbound' 0, for every orbit where the Z-span of the first few lambda_p had rank less than the degree. That was always the case in degree at least 6. The script *recompute_hecke_rings.py* recomputes them from the stored coordinates.)

(parse_omf5 also wrote each eigenvalue in the basis of the order spanned by the first few lambda_p, rounding its coordinates down when the eigenvalue was not in that order. So in 444 orbits (153 of type G, 173 O, 82 Y, 36 P) some stored eigenvalues, and their traces, were the true ones with their coordinates rounded down. *fix_floored_eigenvalues.py* finds and corrects them by comparing every orbit with a full run of omf5 at precision 100. For example, at level 992 the orbit with field x^2 - 8x - 4 had wrong eigenvalues of T(23), T(73), T(89) and T(3,2): lambda_23 had trace 6 instead of 10. In each corrected orbit the true Hecke ring is larger than the stored one, so hecke_ring_index went down.)

(In 25 orbits of type O the field was too small, and the eigenvalues were wrong. When the Hecke operators at the primes up to 19 did not split a space, omf5 gave the old form the field of the last operator it tried, and read its other eigenvalues off an eigenvector of that operator only. If the field of the forms in the space is larger, these are not the eigenvalues of any eigenvector (in 10 of these orbits they were not even integral, and were stored rounded down). For example, at level 460 the orbit with field x - 62 had T(3) = -7, while on its space T(3) has the characteristic polynomial (x^2 - 4x - 41)^3. omf5 PR #75 gives such a form the field of its forms. *fix_old_form_fields.py* replaces these 25 orbits, at 21 levels from 460 to 976, with the forms of a run of omf5 at precision 100 after that PR, with eigenvalue coordinates, which they did not have. Every other orbit of type O was checked against the Hecke matrices at the primes up to 19 and is correct. At levels 768 and 882 the new orbit is the Saito-Kurokawa lift of 256.4.a.n and of 441.4.a.x; it stays of type O, as it is not in the paramodular newspace.)

The file *hecke_evs_3_0/fields.json* has a record for each orbit of degree 14 to 20 with eigenvalue coordinates (types G, P and Y), keyed by 'level', 'field_poly' and 'trace_lambda_p'. Each record gives 'field_disc', 'field_disc_factorization' and 'polredabs' (the polredabs polynomial of the Hecke field), and the certificate they come from: 'hecke_ring_disc_factorization', the factorization of the discriminant of the Hecke ring H. The discriminant of 'field_poly' has hundreds of digits and is not factored. disc(H) = disc(O_K) [O_K : H]^2 has at most 85 digits, and its factorization determines the ring of integers O_K. *verify_fields.py* checks every record against the data without factoring anything.

Both Atkin-Lehner fields give the signs of the paramodular form, not the spinor character of the orthogonal modular form. A form in the space with radical character of conductor d has, for each prime p dividing N, the sign e_p if p does not divide d and -e_p if it does, where e_p is the Eichler invariant at p of the lattice in *qf5db.sage* (+1 when p^2 divides N). See Theorem 10.1 of Dummigan-Pacetti-Rama-Tornaria. When 2 exactly divides N, e_2 was not computed from the lattice but chosen so that the number of primes with e_p = -1 is odd, as it is for every lattice of odd level in *qf5db.sage*; with this choice the stored signs satisfy the rule above for every form.

The subfolder **data_nl_200** contains files named *hecke_ev_3_0_nl_200_{N}.dat*. Each file contains an array of modular forms, as above, for the forms that an earlier classification took for nonlifts, and the array of eigenvalues is for primes p < 200. 'aut_rep_type' and the Atkin-Lehner fields are those of the same form in **data**: 4922 of the 7586 records are of type G, 1629 are oldforms (O), 579 are of type P and 456 of type Y. (Until 2026-11 every record was labelled 'G' and the Atkin-Lehner fields held the spinor character of the orthogonal modular form; *fix_nl_200_types.py* corrected them.) These records have no trace fields, and 'lambda_p_square' is given for p <= 13 only. Their Hecke ring is the order generated by the eigenvalues stored in them (so it can be larger than the Hecke ring of the same form in **data**, which uses p < 100), with 'hecke_ring_index', 'hecke_ring_generator_nbound' and the basis as described above; *recompute_nl_200_rings.py* computes them. (Before that the ring was the one parse_omf5 chose from the first few lambda_p, and in 137 orbits the later eigenvalues had fractional coordinates in it.)

The subfolder **logs** contains files named *hecke_ev_3_0_{N}.log*. Each file contains the log data of the run that generated the corresponding data file.

## Additional_Files

In the main folder there are several more files.

The file *qf5db.sage* is a sage script. When loaded it creates the variable *qf5*, which is an array of arrays of pairs of matrices. *qf5[N]* represents a set of genus representatives for the chosen genus of discriminant N, each pair of matrices consists of a gram matrix of the lattice, and an isometry from the first lattice to this one. All the data was generate with respect to this basis for the space of orthognoal modular forms, and using these isometries for the spinor norm.

The file *qf5.db* is an array of arrays, containing only the gram matrices of the genus representatives in an abbreviated format (lower triangular part). 

The file *hecke_3_0.dat* contains an array of dictionaries, indexed by the level N, whose Nth entry is a dictionary of the matrices of the Hecke operators T(p,1) where p is the smallest prime not dividing N for each of the Atkin-Lehner spaces (keys are the conductors of the spinor norm). The matrices are with respect to the basis described by *qf5db.sage*, and were generated by the PARI/GP code in https://gitlab.fing.edu.uy/grama/quinary.

The file *hecke_all.dat* contains an array of dictionaries, indexed by the level N, whose Nth entry is a dictionary of the matrices of the Hecke operators T(p,1) where p is the smallest prime not dividing N for each of the Atkin-Lehner spaces (keys are the conductors of the spinor norm). The matrices are with respect to the basis described by *qf5db.sage*, and were generated by the PARI/GP code in https://github.com/assaferan/omf5.

The script *recompute_hecke_rings.py* recomputes the Hecke rings of the orbits with coordinates, as described above, and *verify_fields.py* checks *hecke_evs_3_0/fields.json*.

The file *verify.sage* verifies that the data in both files agrees by checking that the characteristic polynomials of the matrices are the same. (Therefore would work even if a different basis is being used). 

The file *discrepancies.sage* specifies the matrices which are not identical, due to a different choice of basis. This occurs in the spaces with non-trivial conductor, as there is a choice to make in the order of the basis elements.

The file *newforms30_dims.txt* contains an array, indexed by the level, such that at index N one has an array containing the dimensions of the irreducible Hecke modules corresponding to newforms which are nonlifts (i.e. the degrees of the number fields over which their Hecke eigenvalues are defined).
